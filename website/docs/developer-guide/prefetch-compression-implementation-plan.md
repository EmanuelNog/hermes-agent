# Prefetch Compression — Standalone Implementation Plan

**Purpose:** implement non-blocking (background) automatic context compaction in
Hermes, from scratch, without relying on the fork's git history. This is the
"develop it yourself" path for upstream — the same feature the fork ships as
`agent/turn_prefetch_compaction.py`, described so an agent can rebuild it against
a current upstream tree.

**Reference implementation:** public fork `github.com/EmanuelNog/hermes-agent`,
branch `prefetch-compression`, file `agent/turn_prefetch_compaction.py` (~412
lines) + 5 gate call sites + config plumbing + 2 test files. The review doc
`website/docs/developer-guide/prefetch-compression.md` is the design spec.

---

## 0. What you are building

Today, when prompt tokens cross the compression threshold, Hermes HALTS the agent
loop and summarizes synchronously (measured: 4m13s dead time on a 519K-token
session). The summary is generated by a pool worker either way — blocking is a
policy choice, not a structural one.

Prefetch compression starts the summary worker slightly EARLIER (inside a "margin
band" below the threshold), in the background, while the loop keeps executing, and
adopts the finished summary at a later safe gate. The existing blocking path stays
untouched as the backstop. **Off by default**: `compression.prefetch_margin: 0`
behaves byte-identically to today.

---

## 1. The trigger math (one function)

New config key `compression.prefetch_margin` — a fraction of the context WINDOW,
subtracted from the blocking threshold:

```
arm at   threshold_tokens − prefetch_margin × context_length
block at threshold_tokens                                  (unchanged)
```

`prefetch_trigger_tokens(compressor, margin)`:
- `None` when margin is `None`/`<= 0`, or context/threshold are `<= 0`.
- Else `trigger = threshold_tokens − int(margin × context_length)`.
- Clamp to `[0, threshold_tokens − 1]` so the blocking path always owns the
  threshold itself.

---

## 2. The arming ballot (one function)

`can_prefetch(agent, messages, tokens) -> (bool, reason)` — refuse arming when ANY
of these hold (each reason is a distinct string, used by tests):

| reason | condition |
|---|---|
| `disabled` | `agent.compression_enabled` false |
| `codex_app_server` | `agent.api_mode == "codex_app_server"` (provider owns compaction) |
| `responses_native` | `agent.codex_responses_native_compaction` (server-side compacts itself) |
| `rotation_mode` | `agent.compression_in_place` false (worker rotates session_id; can't splice) |
| `margin_zero` | `agent.compression_prefetch_margin <= 0` |
| `already_pending` | `agent.prefetch_compaction_pending is not None` |
| `no_compressor` | `agent.context_compressor is None` |
| `awaiting_real_usage` | `compressor.awaiting_real_usage_after_compression` set (post-compaction deferral) |
| `no_trigger` | `prefetch_trigger_tokens` returned None |
| `not_in_prefetch_band` | `tokens < trigger` OR `tokens >= threshold_tokens` |
| `failure_cooldown` | `compressor.get_active_compression_failure_cooldown()` truthy |
| `attempts_exhausted` | `agent.compression_attempts >= max_compression_attempts` |
| `unpersisted_rows` | any message lacks the persisted marker (`region_fully_persisted` false) |

**The persisted-marker invariant is the core safety property:** arming requires
EVERY live row to carry the DB-persisted marker, so the worker's SessionDB commit
can never overlap a main-thread flush of the same rows — this is what prevents
duplicate rows.

---

## 3. Launching the worker (one function)

`launch_prefetch_compression(agent, messages, system_message, tokens, task_id)`:

1. Refuse if a worker is already pending.
2. Admit on the shared compression pool (`_try_admit_compression_job`); if
   saturated, log + return None (skip this cycle).
3. Resolve timeouts (`resolve_context_compression_timeouts`), build a
   `CompressionCommitFence`, set its total-ceiling.
4. **Tag the fence `prefetch_worker = True`** — the shared pipeline reads this to
   keep the blocking-mode client statuses (start/heartbeat/terminal edge) quiet
   for the background run.
5. **Shallow-freeze the snapshot** (`list(messages)`) — the live list may keep
   growing; the snapshot never does. Record `arm_index = len(messages)`.
6. Submit to the pool executor a worker that deep-copies the snapshot and runs
   `compress_context(agent, snap_copy, system_message, approx_tokens=tokens,
   task_id=task_id, defer_context_engine_notification=False,
   commit_fence=worker_fence)` — the SAME worker the blocking path uses, with its
   own commit fence (durable SessionDB mutation happens on the worker; the main
   thread never touches it).
7. Store pending state on `agent.prefetch_compaction_pending` (future, fence,
   snapshot, arm_index, armed_tokens, started_at, idle_timeout, session_id).
8. Stamp `finished_at` via a done-callback (true worker duration, not adoption
   delay).
9. **Publish the fence** to `agent._active_compression_commit_fence` (under the
   existing `_compression_commit_fence_lock`) so `/stop` cancels the worker
   pre-commit.
10. Emit the arm status line: `🗜️ Compacting context (prefetch) — …`.

---

## 4. Adoption (one function)

`adopt_prefetch_result(live_messages, state, result) -> (new_messages, adopted, reason)`:

- Bad result shape → discard (`bad_result`).
- Result identical to live/snapshot → discard (`worker_noop`).
- **Prefix-identity check:** `live_messages[:n] == state.snapshot` (n = snapshot
  length). Any divergence (rewind, edit-resend, competing compaction) → discard
  (`prefix_diverged`). The seam must be byte-identical or the summary is stale.
- Splice: `result_messages + live_messages[n:]` — everything gained after arming
  stays verbatim.
- **Seam-dedupe safety net:** when the worker's commit re-read the durable parent
  and absorbed freshly-flushed suffix rows into its tail, the live suffix repeats
  them. Drop the maximal exact overlap between result tail and suffix head (a
  no-op in the common case; only strips an exact continuation).

---

## 5. The single entry point (one function)

`run_prefetch_compaction_step(agent, messages, tokens, *, system_message, task_id)
-> (action, messages)` — the ONLY function the gates call. Actions:

| action | meaning | caller must |
|---|---|---|
| `adopted` | worker finished + spliced | re-baseline history; skip blocking branch this pass |
| `armed` | worker launched | continue WITHOUT blocking |
| `pending` | worker still running | NOT launch/block a competing compression this pass |
| `none` | nothing to do | normal (blocking) path applies |

Logic:
- No pending state → run ballot; if allowed, launch; return `armed`/`none`.
- Pending state → check session identity (stale worker from a previous session is
  dropped). If future done → clear state, get result, adopt; return `adopted` or
  `none` (with failure report on exception).
- Still running → `decide_threshold_action(pending_exists=True, pending_done=False,
  tokens, threshold)`: below threshold = `none`; at threshold with pending =
  `await` (bounded wait ≤60s, then degrade to `pending` so the blocking pass
  lock-skips on the worker's lease) or `adopt` if done.

---

## 6. The five gate call sites (the integration seams)

Each is the same ~8-line block. The gates call `run_prefetch_compaction_step`
FIRST; on `adopted` they splice the returned messages and re-baseline; on
`armed`/`pending` they skip the blocking compression branch this pass (mirroring
the existing lock-skip semantics).

| file | gate |
|---|---|
| `agent/turn_preflight.py` | pre-API gate + post-tool gate (2 sites) |
| `agent/turn_context_compaction.py` | turn start |
| `agent/turn_overflow.py` | 413 recovery |
| `agent/turn_recovery.py` | Anthropic long-context |

**Critical adoption rule (br-txf.1):** at the pre-API gate, an `adopted` result
must NOT fall through to dispatch the request assembled from the PRE-splice
transcript. Refund the call/budget and return `continue` so the loop re-assembles
and re-measures — mirroring the blocking branch.

## 7. Config plumbing

- `hermes_cli/config_defaults.py`: add `"prefetch_margin": 0.0` under the
  `compression` block, with a comment explaining it.
- `agent/agent_init.py`: parse `compression.prefetch_margin` (clamp `max(0.0,
  float(...))`, default 0.0 on error), thread it through the compression settings
  dataclass, and set `agent.compression_prefetch_margin = cs.prefetch_margin`.

## 8. Reporting (native status registers)

Templates live in `agent/conversation_compression.py` (same registers as blocking
compaction):

- start: `🗜️ Compacting context (prefetch) — summarizing ~{tokens:,} tokens in the
  background so I can keep working...` via `_emit_status` (TUI tags "compacting").
- done: `✓ Prefetch compaction complete — {before} → {after} messages in {seconds}s,
  continuing...` via `_emit_status_kind("compacted", ..., origin="prefetch_compaction")`
  with the TRUE worker duration (stamped by the done-callback, not adoption delay).
- failure: `⚠ Prefetch compaction failed after {seconds}s ({reason}) — continuing
  without it.` via `_emit_warning` (never suppressed on chat platforms).

The blocking-mode registers stay SILENT for the background run: the fence is tagged
`prefetch_worker`, and the shared pipeline's `_announce_compression_start(
emit_client_status=False)` skips the routine start status — which silences the
activity heartbeats and the terminal edge via the existing quiet-engine chain.

## 10. Verification

1. Unit battery: `scripts/run_tests.sh tests/agent/test_prefetch_compaction.py
   tests/agent/test_prefetch_upstream_compat.py` — must be green.
2. Full regression: the compression/compaction family + turn-loop slice.
3. **Live E2E (small scale, `prefetchdev` profile, 64K window, threshold_tokens
   40K, margin 0.15 → arm ~30.4K):** drive a persistent process past the arming
   point; expect `Prefetch compression armed at ~34,849` then `Prefetch compaction
   adopted: 176 → 100 messages, 6 live suffix rows kept`; zero blocking lines; DB
   clean (0 duplicate rows, alternation preserved).
4. **Big scale (manual, `prefetchbig`, 1M window):** armed ~728K, four full-size
   API calls across two turns while the 6m12s worker ran, adoption 758→103, next
   request at 85K (−88%), zero blocking.
5. **Adoption requires a PERSISTENT process** — a one-shot `chat -q` exits before
   the worker lands. Use an interactive REPL or the gateway.

## 11. Invariants checklist (audit before shipping)

- [ ] `prefetch_margin: 0` is byte-identical to current behavior (all new code inert).
- [ ] Scope: automatic in-loop compaction only; manual `/compress`, gateway
      hygiene, Codex app-server, Responses-native untouched (last two refused by ballot).
- [ ] Arming requires fully-persisted region (no duplicate rows possible).
- [ ] Staleness acceptable by design: summary covers up to arming point; newest
      margin-worth survives verbatim in tail.
- [ ] Seam never splits a tool pair (splice at the arming cut).
- [ ] `/stop` cancels worker pre-commit via published fence.
- [ ] Worker failure clears state + lets blocking backstop proceed (cooldown ladder).
- [ ] Process death between arm and adopt self-heals (worker's DB commit durable).
- [ ] Pending state from a previous session dropped at the gate.
- [ ] Blocking backstop re-checks after adoption.
- [ ] Rotation mode refused.
- [ ] Pre-API adoption re-assembles before dispatch (br-txf.1).
- [ ] Ballot waits for real reading after compaction (br-txf.2).
- [ ] `micro_compact` + prefetch unsupported (both rewrite sent history).

## 12. Cost / trade-off (by design)

A session that crosses the arming point but ends below the blocking threshold
still pays the background summary. The margin is the spend/latency knob — a
larger margin arms earlier (more background summaries), a smaller one later.
Recommend `0.05` on a 1M window (arm ~60% fill, block at 65%).
